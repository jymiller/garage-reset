Completion pipeline

What one quest completion computes. A single status → 'done' flip fans out into every progression counter and the right celebration sound.

The one subtle rule

  • The six computations run twice: once as a read (to choose the sound, before setState) and once as the pure state transition (inside setState). This split is what keeps sound correct and StrictMode-safe. See request lifecycle and ADR-0005.
  • Only bonuses (mission, combo) are stored as XP (bonusXp); base XP is always derived from tasks.
