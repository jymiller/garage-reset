Code patterns

The handful of shapes you'll see repeated across the codebase. Match these when adding code. Full catalog in the pattern inventory.

1 · Pure derivation function extractable

Everywhere in game.ts / lib.ts — no React, no storage.
// game.ts — a value computed from state, never stored
export const xp = (tasks: Task[], person?: PersonId) =>
  doneTasks(tasks, person).reduce((sum, t) => sum + taskXp(t), 0)
Why: one source of truth, trivially testable, forward-compatible saves. Start any test suite here.

2 · Compute-SFX-outside / mutate-inside preserve this

store.tsx — setTaskStatus, toggleStep.
// side-effects read the render-time snapshot, BEFORE setState
if (completing) playCompletionSfx(state, id)
// the updater is pure — StrictMode double-invokes it in dev
setState((s) => applyCompletion(s, id))
Why: firing sound inside the updater would double-play and could double-count combos. See ADR-0005.

3 · Presentational screen reading useStore()

All src/screens/* except Garage / SoundTest / TitleScreen.
const { tasks, setTaskStatus } = useStore()
// read derived values, render, call actions — no local persistence
const top = nextTasks(tasks, 1, who)[0]
Why: views stay dumb; a backend swap behind the store leaves them untouched.

4 · Extend-don't-migrate state growth

store.tsx initialState() — every feature wave.
// new counters hydrate with a fallback; old saves never break
combo: parsed.combo ?? 0,
lastDoneAt: parsed.lastDoneAt ?? null,
// steps[] are re-attached from the seed by task id on load
Why: mechanics were added wave after wave with zero destructive migrations.

5 · Lazy-loaded heavy subtree good practice

Garage.tsx defers Plan3D (and all of three.js).
const Plan3D = lazy(() => import('../garage/Plan3D'))
// three.js only downloads when the MAP tab is opened
<Suspense fallback={<div>LOADING 3D…</div>}><Plan3D … /></Suspense>
Why: keeps the initial bundle small for players who never open the map. See ADR-0003.
